**第一版只处理“支付成功，但订单仍待支付”，完成诊断、审批、执行、验证和故障恢复这一条闭环。** 以下清单可以直接用于拆分开发任务。

这里的“第一版”是可用于面试演示的版本，包含异常路径和验证，不只是正常流程跑通。

### 1. 业务模拟与演示数据

| 编号 | 功能             | 第一版范围／验收标准                                         |
| ---- | ---------------- | ------------------------------------------------------------ |
| B01  | 模拟订单服务     | 查询订单、金额、关联支付单、状态和版本号                     |
| B02  | 模拟支付服务     | 查询支付状态、金额、关联订单；只使用模拟资金数据             |
| B03  | 模拟回调记录     | 查询回调是否送达、处理结果和失败原因                         |
| B04  | 受控订单修复接口 | 重新核验支付事实，满足条件后推进订单；支持操作 ID 幂等和结果查询 |
| B05  | 预置演示场景     | 包含回调失败、正常延迟、金额冲突、证据缺失、已经修复、订单关闭 |
| B06  | 场景重置         | 可恢复演示数据，重复运行同一个案例                           |

### 2. 任务创建与 AI 诊断

| 编号 | 功能           | 第一版范围／验收标准                                         |
| ---- | -------------- | ------------------------------------------------------------ |
| A01  | 创建诊断任务   | 输入订单号创建任务；同一订单同时只允许一个活动处置任务       |
| A02  | 只读工具调用   | 查询订单、支付、回调和历史处置记录；校验参数与访问权限       |
| A03  | 多步证据查询   | Agent 根据已有信息选择下一步工具，而非固定获取所有数据       |
| A04  | 结构化诊断结果 | 输出异常分类、原因、证据引用、信息缺口及建议动作             |
| A05  | 诊断结果校验   | 检查字段、证据编号和允许的动作；格式错误仅允许有限次纠正     |
| A06  | 不处置分支     | 支持“无需处理”“等待复查”“转人工”；证据不足时不得强制生成修复方案 |
| A07  | 调用约束       | 限制模型轮数、工具次数、任务时长；检测连续重复且没有新增信息的调用 |
| A08  | 费用记录       | 记录模型用量和估算费用；调用前检查剩余预算，超限后停止后续调用 |

“等待复查”第一版只给出结论，由用户稍后重新发起任务，暂不增加定时调度。

### 3. 处置方案与人工审批

| 编号 | 功能         | 第一版范围／验收标准                                         |
| ---- | ------------ | ------------------------------------------------------------ |
| P01  | 创建处置方案 | 只允许“核验支付并推进订单状态”这一种写动作；保存参数、依据和方案版本 |
| P02  | 审批预览     | 展示订单当前情况、证据、拟执行动作及预计影响                 |
| P03  | 批准或拒绝   | 保存审批人、时间、意见和结果                                 |
| P04  | 审批权限     | 使用预置操作员、审批员账号，后端校验权限；无需开发账号管理后台 |
| P05  | 审批有效性   | 审批绑定方案版本、参数和有效期；旧方案、过期审批不得执行     |
| P06  | 重复审批处理 | 重复点击或重复请求不会重复触发有效执行                       |

### 4. 执行与结果验证

| 编号 | 功能               | 第一版范围／验收标准                                         |
| ---- | ------------------ | ------------------------------------------------------------ |
| E01  | 执行前再次校验     | 重新确认支付成功、金额及关联关系一致、订单状态允许转换       |
| E02  | 状态变化拦截       | 审批后订单关闭或条件变化，停止执行；已经修复则记录无需再次操作 |
| E03  | 幂等执行           | 同一操作始终使用同一个操作 ID；模拟下游保证该 ID 不产生重复业务效果 |
| E04  | 结果待确认处理     | 请求超时不能直接视为失败；先查询操作结果，再决定后续动作     |
| E05  | 执行结果验证       | 查询最终业务状态，由代码确认是否达到目标                     |
| E06  | 有限重试与人工接管 | 明确失败且允许重试时有限重试；无法确认结果时保留待确认状态并提示人工处理 |

**模型负责提出建议，写操作由审批后的 Java 执行服务发起。**

### 5. 持久化与故障恢复

| 编号 | 功能           | 第一版范围／验收标准                                         |
| ---- | -------------- | ------------------------------------------------------------ |
| R01  | 任务状态持久化 | 保存诊断、待审批、执行中、结果待确认、完成、失败等状态       |
| R02  | 步骤记录       | 保存模型输出、工具调用、方案、审批及执行结果，关联同一任务   |
| R03  | 重启恢复       | 进程重启后扫描未完成任务，根据状态恢复；已完成的写操作不得直接重做 |
| R04  | 执行任务认领   | 防止并发执行者同时取得同一任务；支持异常退出后的重新认领     |
| R05  | 任务取消       | 执行前可取消；写请求已发出后，必须确认结果，不能把取消解释为撤销业务操作 |
| R06  | 历史记录查看   | 按时间展示实际发生的步骤；查看记录不会重新调用模型或执行工具 |

诊断中断时，可以从已保存的证据重新发起模型请求，**不要求恢复模型内部生成过程**。人工审批等待时间应与单次诊断、执行超时分别计算。

### 第一版明确不做

- 退款、扣款、地址修改、物流异常和批量自动修复。
- RAG、向量数据库、多 Agent、模型微调。
- 通用工作流引擎、可视化流程编辑器。
- Kubernetes、完整微服务体系。
- 为了展示技术栈而额外引入 Redis、消息队列、Elasticsearch。
- 真实商户接入、真实资金和生产规模承诺。

**开发顺序建议：先完成模拟服务和确定性的审批执行闭环，再接入 Agent，随后验证恢复机制，最后补齐评测与演示。** 状态持久化、操作 ID 和审批版本从第一阶段就设计进去。
