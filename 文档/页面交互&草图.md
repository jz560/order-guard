上图是第一版的关键页面草图，订单、金额和时间均为示例。**实际开发建议采用“任务列表＋统一任务详情页＋操作弹窗”**，图中的诊断、审批、执行结果是同一详情页的不同状态，减少页面跳转。

图中右下角“修复成功”和“转人工”是两种结果样式示意，实际只展示当前结果。

**1. 任务列表与新建诊断**

| 项目         | 设计                                      |
| ------------ | ----------------------------------------- |
| 输入         | 订单号、任务状态筛选                      |
| 列表内容     | 任务 ID、订单号、状态、简短结果、创建时间 |
| 操作         | 查询、重置筛选、新建诊断、查看详情        |
| 新建弹窗     | 必填订单号；按钮为“取消”“开始诊断”        |
| 提交反馈     | 提交期间按钮显示“正在创建…”并禁用         |
| 已有活动任务 | 提示“该订单已有进行中的任务”，打开原任务  |
| 校验失败     | 输入框下展示错误；无权限时不泄露订单详情  |
| 空列表       | 提示“暂无符合条件的任务”，保留新建入口    |

创建成功后直接进入详情页，不要求用户回列表寻找任务。

**2. 任务详情：诊断状态**

页面上方固定显示任务 ID、订单号、任务状态和更新时间。主体左右分栏：

- **左侧：证据列表。** 显示来源、查询时间、关键事实；点击展开完整业务字段。查询失败也要显示，不能伪装成“没有记录”。
- **右侧：诊断结论与建议。** 展示异常分类、结论、证据引用、信息缺口及下一步。

图中的查询顺序仅为示例，**实际展示按发生时间追加的步骤记录**，不把 Agent 的查询路径写死。

| 状态               | 展示与操作                                   |
| ------------------ | -------------------------------------------- |
| 诊断中             | 当前步骤、已取得证据、已用时间；允许取消     |
| 无需处理           | 明确说明原因及证据；查看记录、返回列表       |
| 等待复查           | 展示等待原因和建议复查时间；允许稍后重新诊断 |
| 证据不足／冲突     | 展示缺失或冲突字段，提示转人工               |
| 可修复             | 展示处置方案，切换到待审批视图               |
| 调用失败或预算耗尽 | 展示停止原因和已有证据，不显示虚假的完整结论 |

点击结论中的 `E01` 等证据编号，定位并展开对应证据。

**3. 任务详情：方案审批状态**

审批区域展示：

- 操作对象与当前业务状态。
- 拟执行动作、固定参数及预计影响。
- 诊断依据。
- 方案版本、有效期。
- “执行前将重新核验业务状态”的说明。

**方案参数不可在审批页面直接编辑。** 第一版如果方案不合适，应拒绝并重新发起诊断。

| 操作             | 交互与结果                                             |
| ---------------- | ------------------------------------------------------ |
| 批准方案         | 打开确认弹窗，重述订单号与预计状态变化；确认后提交审批 |
| 拒绝方案         | 打开弹窗，必填拒绝理由；提交后展示审批记录             |
| 非审批员查看     | 显示“等待有权限的审批员处理”，不提供审批按钮           |
| 审批过期         | 禁用按钮，提示“方案已过期，请重新诊断”                 |
| 重复点击         | 请求期间禁用按钮；重复请求返回已有审批结果             |
| 提交时状态已变化 | 更新页面并提示最新结果，不继续显示可审批状态           |

批准提交成功后的提示应是：

> 审批已通过，系统正在重新核验并准备执行。

不能提示“修复成功”。

**4. 任务详情：执行与结果状态**

| 状态             | 提示文案                                   | 允许操作               |
| ---------------- | ------------------------------------------ | ---------------------- |
| 执行前复核       | 正在重新确认支付与订单状态                 | 查看记录               |
| 执行中           | 修复请求已发出，正在等待结果               | 查看记录、刷新状态     |
| 结果待确认       | 请求超时不代表失败，系统正在查询操作结果   | 查看记录、刷新状态     |
| 修复成功         | 已验证订单状态为已支付                     | 查看验证证据、返回列表 |
| 目标已达成       | 订单已由其他流程修复，本任务未重复操作     | 查看证据               |
| 条件变化被拦截   | 当前订单不再满足修复条件，未执行本次修复   | 查看变化详情           |
| 转人工且结果未明 | 暂无法确认操作结果，请先核实，禁止重复修复 | 查看操作 ID、执行记录  |

**“刷新状态”只读取状态，不触发重新执行。** 第一版不提供手动“强制修复”按钮；结果未明时也不提供重新诊断入口来绕过限制。

成功结果需要展示最终订单状态、验证时间及验证来源。转人工结果需要展示具体原因、已确认事实和仍需核实的事项。

**5. 通用交互规则**

| 情况               | 页面行为                                                     |
| ------------------ | ------------------------------------------------------------ |
| 取消任务           | 弹窗确认；后端确认取消成功后才能显示“已取消”                 |
| 取消时写请求已发出 | 提示“操作已发出，无法直接取消，系统将继续确认结果”           |
| 页面刷新或重新打开 | 重新读取服务端状态，恢复当前视图                             |
| SSE 断开           | 显示“实时连接已断开，正在重连”；保留已加载内容               |
| 恢复连接           | 重新获取完整当前状态，避免遗漏事件                           |
| 数据过期或无法刷新 | 展示最后更新时间；审批等关键操作暂时禁用，提示刷新后再试     |
| 查看执行记录       | 侧边抽屉展示时间、步骤、摘要、结果；展开可查看脱敏参数       |
| 错误提示           | 说明发生了什么、是否已执行、下一步能做什么，避免只显示“操作失败” |

前端最终需要实现 **2 个页面、3 个操作弹窗和1个记录抽屉**：

- 任务列表页、任务详情页。
- 新建诊断、审批确认／拒绝、取消确认弹窗。
- 执行记录抽屉。

演示场景选择、数据重置和故障注入另放在仅演示环境可见的“演示控制”入口，避免混入日常业务操作。
