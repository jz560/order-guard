# 012 — T12 工作台连接既有诊断 API

## 决策

采用现有 Vue/TypeScript 依赖实现两个哈希路由（列表和任务详情）及原生 dialog 新建弹窗，不引入路由库、状态库或 UI 套件。当前只有两页，无动态嵌套路由；哈希链接支持重载恢复，静态服务器无需额外 history fallback。

登录沿用 T06 Basic + Spring Session，Basic 只发首次认证请求，之后依赖同源 Cookie。写请求即时获取 CSRF；不持久化密码/Authorization，不使用前端角色推断授权，创建入口由 /api/me 的 allowedActions 决定，证据读取以详情 allowedActions 为准，后端仍执行授权。

创建中禁止重复提交。同订单失败重试保留原幂等键（当前页面内存）；不自动重试写请求。关闭/重载后的冲突由后端 order_guard 处理，不能声称终态任务跨页面幂等。

详情读取持久化事实与已校验结论，不直接渲染模型自由文本。证据以 UUID 绑定，E 编号只是当前列表中的定位别名。保留来源/时间/业务版本及 JSON，查询不可用不是空集合。刷新失败保留旧快照并提示过期；路由切换后的旧响应不更新页面。

T12 手动只读刷新，不提前实现 T13 SSE 或审批/执行操作。原始草图中的取消、审批等依任务边界留在 T13。未采用客户端模拟诊断流程，页面创建实际调用服务端，Worker 独立推进。

## 验证与适用边界

前端交互测试采用 HTTP 替身；另用隔离 PostgreSQL、实际 backend/simulator JAR 和浏览器验证登录、创建、重复任务跳转、证据定位、重载和退出。模型使用无费用替身。详细命令和结果见 [T12](../tasks/T12.md)。没有改动 API 响应、迁移、审批语义和业务状态机。
