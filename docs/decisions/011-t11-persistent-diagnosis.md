# 011：有规则约束的持久化诊断

T03 未证明 Agent 优于规则，且出现了引用齐全但时间窗口判断错误。T11 因此保留确定性业务政策作为门槛：模型选择只读查询、提交引用及公开结论，应用验证证据、动作和结论；只有完整、匹配的事实才能生成冻结方案，审批和执行契约不变。

每次 Worker 认领最多运行一轮模型和这一轮要求的只读工具。模型与工具调用前分别持久化意图和计数；模型输出、证据逐步提交。短事务锁任务并校验 owner/epoch/version/租约，远程调用在事务外。异常数据库写入不释放租约，恢复依赖租约到期；模型调用次数已经占用，防止重启重置预算。

恢复采用“已保存证据重新构建提示”，不持久化供应商私有会话或隐藏推理，不尝试重建完全相同的答案。已保存证据可复用；丢失响应可能额外产生模型费用。旧 Worker 的外部请求无法撤回，但不能覆盖新状态。缺失响应的意图仍可追踪，用量未知。

WAIT 使用现有 DIAGNOSING/next_run_at，而不是增加状态。复查增加批次，只使用该批次证据，保留所有旧快照；轮数和总时限不重置，最多复查两次。任何不能安全自动结束的情况转人工并保留 guard。

历史工具读取本应用的真实执行记录，因为下游没有按订单列举操作的接口。它只声明此范围，不能证明不存在系统外操作。旧 TEST_STUB 流程保留为显式 legacy-test，避免历史 T07—T10 工程实验被诊断结果改变；新默认模式为 agent，端到端测试单独覆盖真实只读查询和持久化恢复。

非 MANUAL 结论目前要求四类证据，放弃早停优化以降低引用和规则判定复杂度；本阶段不声称工具选择带来成本优势。费用估算暂不可用，不猜测价格；记录供应商可获取的 token、耗时、模型和提示词版本。真实付费评测不在普通验证中执行。

验证包括规则和恶意输出单元测试、真实 PostgreSQL 的预算/租约/回滚测试、独立 JVM 双 Worker/HTTP/进程 KILL 后恢复测试，最终结果见 [T11](../tasks/T11.md)。
