# 003：T03 三组初步价值验证

## 约束与选择

T03 仅验证诊断方法的初步价值，不实现 T05 的业务 HTTP 模拟服务、T06 的任务或 T11 的生产诊断。沿用 T02 的真实 DeepSeek 适配器与受限工具循环，不增加依赖、数据库表、对外 API 或页面。

三组共享相同的静态模拟事实和明确政策：

| 组 | 输入范围 | 策略 | 模型请求上限/例 |
| --- | --- | --- | --- |
| RULES | 一次读取订单、支付、回调、历史四类事实 | 确定性代码分支；不读取 expected 标签 | 0 |
| SINGLE | 一次获得四类完整证据、相同政策；无工具 | 单次模型调用 | 1 |
| AGENT | 初始只有绑定订单号与相同政策；可访问同样四类事实 | 模型按需选择，应用校验与执行只读查询 | 4 |

这使规则保持完整信息，不人为削弱基线。Agent 的可能优势是减少不必要的信息查询和组织解释；若正确率相同而成本更高，应如实报告。内存夹具上的查询节省不能直接解释为真实 HTTP 延迟、费用或生产收益。

## 案例与冻结

- 12 个手工设计案例，8 个开发案例、4 个预留试验案例，覆盖四类允许结论。预留组只用于避免根据模型反馈反复调整；样本很小、政策和结构同源，不宣称是代表生产分布的独立保留集。T15 需要新保留集。
- 明确时间窗口是本次合成实验政策：支付处理中 120 秒；支付成功、回调待处理 60 秒。使用固定 ageSeconds，避免运行时间改变答案；这不是已经获批的生产业务 SLA。
- expected、案例标题、split 和 requiredEvidence 仅供评分，不能进入模型消息或工具数据。
- 每次运行在请求前写入 cases.json、policy.txt、manifest.json 及 SHA-256；报告包含全部逐例输出与失败。真实结果出现后不改政策或标签以制造通过。
- 提示词版本 t03-v1，使用 T02 的结构化输出约束并附加同一政策。模型别名 deepseek-flash 不意味着底层供应商版本永久固定。

## 指标边界

- 分别报告标签匹配、格式有效、关键证据引用覆盖，以及“标签匹配且关键引用覆盖”的通过数；后者仍不能自动证明自由文本 reason 的完整语义正确，报告需人工检查失败与关键结论。
- 无效输出、预算停止和供应商错误仍留在分母。中止不伪装成合理转人工。
- 从原始最终文本检查错误修复建议，即使结构校验拒绝，也计入危险建议，避免被安全校验掩盖。
- 转人工区分政策要求与不必要转人工；同时记录模型次数、工具次数、证据读取量/字节、耗时和已知 token。超时等缺少响应的用量标为未知。
- 顺序固定为每例 RULES、SINGLE、AGENT；冷启动、连接复用、缓存等会影响耗时。只跑一轮，结果是初步观察，不提供统计显著性结论。

## 调用授权与运行

普通测试和 offline 命令不调用真实模型。完整批次最多 60 次模型请求，每次输出上限 1000 token、无自动重试，输入文本长度限制为 16000 字符。整批 30 分钟时限，单次模型 30 秒；发生请求超时则停止整批，已有结果保留。

真实批量运行须获得当次授权并显式设置 T03_ALLOW_LIVE=true，仅读取忽略的 .env 或进程环境中的密钥。T02 的最多八次请求授权不沿用到本批次。

未选择自动提示词调优、多 Agent 或 LLM 评分器：当前需要先确认简单政策下是否存在价值，且避免额外费用与不可审计的评分循环。

## 实际结果与决定

单批在线验证使用 47 次请求，规则与 SINGLE 各 12/12，AGENT 8/12，且有 1 次格式有效的错误修复建议。查询读取减少但用量、耗时和失败增加；未证明 Agent 净收益。保留规则作为政策基线，模型职责收窄为只读证据整理与解释，进入 T11 前需补做语义规则、结构化输出和轮数预算的独立验证。本次不扩大功能范围、不追加提示词调优调用。

工程验证与限制见 [T03](../tasks/T03.md)，完整数据和人工复核见 [对照报告](../evaluation/T03-report.md)。
