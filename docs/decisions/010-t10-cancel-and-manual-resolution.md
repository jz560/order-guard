# 010：取消竞争与有证据的人工结案

## 约束与选择

取消只能阻止尚未获准开始的写操作。T09 在锁任务的事务内创建执行意图并切换 EXECUTING，因此 T10 使用同一任务行锁、预期版本和状态条件更新。取消清除租约/下次运行时间并增加 epoch/version，使旧诊断或执行复核 Worker 写回失败；已经存在 execution 时拒绝取消，保留自动确认流程。

采用 FINISHED/CANCELLED 表达取消，不增加状态枚举。操作员可以取消范围内任务；审批员可接管及结案，这是沿用现有两角色的最小授权，无新增账号管理系统。

人工接管记录账号、原因和原操作 ID，切换 MANUAL 并停止自动推进，保留订单 guard。它不撤回已发出的网络请求，旧 Worker 的结果写回受版本与租约约束。T09 自动转人工的任务可直接结案。

人工结案不接受主观的“已成功/未执行”结果。NO_EXECUTION 只在没有任何 execution 时生效；有意图时，CONFIRM_OPERATION 只读查询同一 ID，验证绑定参数，明确拒绝或完整业务验证成功才释放限制。查询在事务外，落库时重查任务版本，证据、状态、处置记录、审计及 guard 释放同事务。404 不证明未执行，无法核实时保持 MANUAL 和限制。

新增 task_handling 不可变记录，唯一 `(task_id, action, expected_version)` 处理响应丢失后重试；相同请求返回原记录，不重复执行网络确认或状态变更，冲突内容返回 409。actor 取认证上下文，备注不作为授权或业务证明。

## 未采用方案及边界

不允许强制清 guard、不支持任意备注声称业务成功、不增加手工重发修复按钮、不把取消解释成业务撤销。当前模拟服务没有“永久确认未发送”的额外协议，因此已存在意图但查不到记录的任务可能长期保留限制，不能仅凭人工确认解除。

不会修改 T09 的业务参数、原操作 ID 或审批期限。处理迟到请求依赖下游对同一 ID 的最终结果与幂等事务；只有确认终态及必要的业务事实后才释放限制。

## 验证

真实 PostgreSQL 验证取消与执行意图竞争、租约失效、旧 Worker 拒绝、拒绝/成功结案、回滚与记录不可变。独立服务验证角色/范围/CSRF、重启重放、未知结果防绕过、服务端重新查询原操作后结案。完整结果见 [T10](../tasks/T10.md)。
