# T06：任务创建、订单限制与访问范围

## 问题与约束

T05 已提供独立模拟业务服务。T06 要求创建、列表、详情、基础审计和预置权限；同订单并发只能有一个活动任务，重复请求必须能返回原任务。网络查询不能放进数据库事务，未知结果的订单限制不能因任务转人工自动释放。

## 选择

- 后端 Flyway V2 新增 `task`、`order_guard`、`task_creation_request`、`evidence`、`audit_event`。只创建 `QUEUED` 任务；状态枚举沿用原状态图，T06 没有状态推进、审批、取消或执行入口。
- 新请求先检查账号角色与服务端配置的订单范围，再通过 HTTP 只读查询模拟订单。网络调用设置 2 秒连接/3 秒请求超时、不重试、不跟随重定向。返回订单 ID 必须与请求一致，校验状态、金额、币种、版本及支付引用后才保存。
- 初始订单查询快照、任务、订单限制、幂等键映射和创建审计同事务落库；后续证据/列表/详情查询只读本地持久化数据，不重新执行诊断或修复。此快照只证明创建时查询结果，不是执行时的最新事实。
- `Idempotency-Key` 以认证账号为作用域，绑定固定订单。请求记录先 `INSERT ON CONFLICT` 再加行锁；同键同订单返回原任务，不同订单 409。不能信任请求体中的用户身份。
- `order_guard.order_id` 主键保证跨账号、跨幂等键的唯一占用。先插入候选任务 ID 的订单限制，利用延迟外键在同一事务内补齐任务；冲突请求等待后读取已有任务。事务提交时不允许孤立限制，任务活动状态另有部分唯一索引兜底。
- 新幂等键复用已有订单限制时记录 `TASK_REUSED`；同幂等键重放不重复追加审计。限制、初始证据或审计写入失败时整个创建事务回滚。
- 重复请求优先从本地查询，模拟服务不可用时仍能返回原任务。T06 没有释放限制的路径；即便任务进入 `MANUAL` 并保留 UNKNOWN 限制，也返回原任务。未来释放策略必须由 T09/T10 明确实现。
- 预置 `operator`、`approver` 两个账号，密码从环境注入、运行时 BCrypt 编码，不新增账号管理后台。账号配置只在纯 demo/test profile 生效；其他或混合 production profile 不启用预置账号。空密码禁用对应账号。
- 当前 API 通过 HTTP Basic 建立 Spring 会话认证，并启用 CSRF 防护。认证上下文保存到 HttpSession，避免无状态反复认证触发 CSRF 令牌轮换。`GET /api/auth/csrf` 返回令牌，客户端保留该会话 Cookie，写请求附带返回的 header/token；各账号使用独立会话，服务重启后重新认证并获取令牌。T12 的页面登录另行实现。
- 操作员可创建和读取，审批员可读取。两个角色都只能访问自己的配置订单前缀，默认 `T05-ORDER-`。列表过滤、详情、证据、审计、重复创建均执行服务端范围检查；任务不存在与越权统一返回 404。可见范围是演示级前缀，非生产多租户 ACL。
- `POST /api/auth/logout` 使用 Spring 的退出处理器并要求有效 CSRF 令牌，销毁当前认证会话；不会取消任务或释放订单限制。

## 替代方案与边界

- 不采用先查询再无约束插入：多进程并发会创建重复任务。
- 不使用 JVM 锁代替数据库约束：无法覆盖多个服务实例。
- 不按创建者私有化任务：操作员与审批员需要查看共同订单范围内的任务；以订单访问范围控制可见性。
- 不在创建时生成固定诊断结论或方案：任务推进属于 T07，Agent 证据循环属于 T11。
- 不为本任务增加前端页面、模型调用、后台调度、OAuth/JWT 平台或账号管理功能。

查询列表的 items 与 total 为两次只读查询，并发新增时可能暂时有差异；API 不是数据库历史快照。审计使用递增 ID 游标，默认返回 50 条、最多 100 条。创建证据只包含订单快照，支付、回调和诊断过程证据将在 T11 增加。

实际验证状态及独立进程实验见 [T06](../tasks/T06.md)。
