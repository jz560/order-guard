# T03 按需查询 Agent：中文运行记录

这里把原始 JSON 日志改写成中文，展示程序实际记录到的查询、模型公开回复和结束结果。金额按整数最小货币单位换算，时间按 Asia/Hong_Kong 展示。所有业务数据都是模拟数据。

模型刚开始只知道绑定的订单号和诊断政策；案例标题与预期结果是供读者理解的评分信息，没有发给模型。下文对错误结论保留原意，并将复核说明单独标出。这里不补写模型未公开的内部思考，也没有重新调用模型。

**怎样理解一轮：**程序把当前信息发给模型；模型可以请求一个或多个查询；程序逐项校验参数、读取证据并返回结果。模型说“一起查”或“并行查”，表示一轮提出了多个查询请求；本实验程序实际逐项执行。模型通常需要下一轮才能根据新证据给出结论。因此“4 轮模型调用”和“4 次查询”不是同一件事。

**结果区别：**“程序正常结束”只说明输出通过格式和引用检查；“自动评分通过”还要求结论符合预期并引用关键证据。两者都不能保证说明文字中的每个细节正确。

## 常见词的中文意思

| 日志中的词 | 中文意思 |
| --- | --- |
| 待支付 / 支付成功 | 分别是订单状态和支付状态，可能暂时不一致 |
| 回调 | 支付侧向订单侧通知支付结果的过程 |
| 重新核验 | 重新确认支付与订单事实，再决定后续；不是直接写入订单 |
| 转人工 | 交给人员进一步核对，不能解释为已经修复 |
| 结果未知 | 还不能确认某项操作的结果，不能简单认定失败或未执行 |
| 证据引用 | 模型列出其判断依据来自哪些已查询记录 |
| token | 模型服务计算文本处理用量的单位，不等于汉字数 |
