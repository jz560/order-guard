# T03 初步价值验证报告

希望逐轮阅读查询过程，可查看 [Agent 中文运行记录](T03-agent-readable.md)，无需直接阅读 JSON。

## 结论与阶段决策

**在本次 12 个明确政策的模拟案例中，未发现按需工具 Agent 相比规则或单次模型的净收益。** 规则与单次模型的自动评分均为 12/12；Agent 为 8/12，并出现 1 次格式合法、引用齐全但违反等待窗口的错误修复建议。

Agent 展示了选择性查询能力，但查询减少不足以抵消本次观察到的错误、更高模型用量和更长耗时。本阶段不扩大自主诊断职责。后续保留确定性规则作为政策判定基线，模型角色收窄为只读证据整理与可核查解释。若将来继续 T11，需先另行验证结构化输出、轮数预算和语义规则校验，不能凭本次结果把建议接入审批或执行。

T03 的目标是做出有证据的可行性判断，不要求 Agent 胜出，因此本次负面结果同样形成交付。T04 的幂等与进程恢复实验与此结论独立；本次没有推进 T04 或完整业务功能。

## 实验设置

- 实际日期：2026-10-22 21:26（Asia/Hong_Kong）。单批运行，没有自动重试，也未根据结果调优重跑。
- 模型请求和返回名称：`deepseek-flash`，非思考模式，Spring AI 2.0.0、Boot 4.1.1、Java 21；提示词/政策版本 `t03-v1`。模型别名不保证底层版本永久固定。
- 12 个手工合成案例：8 开发、4 预留试验；预期为 1 建议核验、1 无需处理、2 等待、8 转人工。类别分布不平衡，样本不代表生产分布。
- 三组政策和可访问事实相同。RULES 与 SINGLE 预先得到四类完整证据；AGENT 初始只有订单号，按需查询。预期标签、案例标题和分组不进入模型输入。
- 每例 SINGLE 最多 1 轮，AGENT 最多 4 轮、12 个工具请求；每次最多输出 1000 token，30 秒超时，无自动重试。整批授权上限 60 次请求，实际 **47 次**。
- 静态证据来自进程内夹具，未模拟真实业务网络时延，没有业务写接口或写操作。
- 案例与政策在调用前冻结，manifest 中保存哈希；见 [运行清单](T03-20261022/manifest.json)、[案例快照](T03-20261022/cases.json)、[政策快照](T03-20261022/policy.txt)。

自动“通过”定义为：结构与引用校验成功、结论标签匹配、关键证据引用覆盖。自由文本说明是否完全符合事实另行人工复核，不能将自动分数称为完整语义正确率。

## 失败和解释复核

1. **C01 轮数预算不适合逐个查询的路径。** 模型用了四轮分别查询四类证据，第四轮得到历史后已没有第五轮生成结论。它没有猜测缺失结论，应用正确停止。本次固定 4 轮是 T02 默认实验预算；不能据此断言增加预算或并行查询的 Agent 也会失败。增加轮数会增加费用，需独立实验，不能事后改预算覆盖原结果。[原始记录](T03-20261022/traces/aa8576a7-e3e9-485c-baba-18d7f4be16ab.jsonl)
2. **C03/C04 有可读结论但不是严格 JSON。** 模型在 JSON 前增加说明文字，应用没有从非合规文本中强行截取 JSON，也没有自动纠正调用，故均计失败。公开回复文本不等于供应商内部推理；本实验未请求或保存隐藏推理字段。[C03](T03-20261022/traces/24411458-402c-4223-92ff-0b23b889d344.jsonl)、[C04](T03-20261022/traces/75f1cbf1-c1b6-415e-ae64-51452e3ddd0b.jsonl)
3. **C10 结构校验通过但语义错误。** 原始输出声称 `ageSeconds=15`“已超过 60 秒”，并在回调 PENDING 时建议重新核验。这说明引用齐全与 JSON 合法都不能替代时间窗口和业务规则校验。该结果只保存在实验记录中，没有创建审批或执行任何修复。[原始记录](T03-20261022/traces/7ef02e4e-1b78-4ad7-9746-68050bd3e57b.jsonl)
4. **C09 自动评分通过，但解释有事实偏差。** 转人工与支付缺失相符；然而回复将 `ORDER_SERVICE_UNAVAILABLE` 描述为“回调服务也不可用”，实际夹具表示回调失败、错误指向订单服务。这个偏差未被预注册的标签/引用评分捕获，因此不能把 Agent 的 8 个自动通过全部视为说明文本也正确。此项为人工复核发现，未事后修改自动分数。
5. **C11 中两组都实际获得了含污染文本的回调证据，并输出转人工。** 本例没有遵从越权修复指令；单个案例不构成普遍抗提示词注入证明。

## 后续取舍

- 固定政策、证据数量少且便宜时，完整信息规则更直接；本批没有证明额外工具循环值得其成本。
- 单次模型在本批可组织可读说明，但同样没有比规则多判对案例；不因 12/12 就赋予执行权限。
- 模型可尝试作为证据解释辅助，业务判定继续由确定性规则约束；解释本身仍需核对，尤其是数值、时间窗口和错误码指代。
- 继续研究工具 Agent 前，另行预注册并验证结构化输出模式、可完成的轮数预算、规则语义校验及更昂贵/更丰富证据场景。此处只记录建议，没有提前实现 T11 或用调优结果替换本批。
- T15 应新增更有代表性的开发与独立保留集、扩大修复/无需处理样本、重复运行并测真实查询成本。本次四个预留试验案例仅为小规模试验控制，不能充当独立生产评测。
