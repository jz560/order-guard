# T05：完成业务模拟场景

## 范围与前置条件

依赖 T04，其真实 Java/PostgreSQL 幂等、响应丢失、SIGKILL 恢复验收记录已存在。本次保留 T04 实验协议和独立 schema，在常驻 simulator 中实现正式模拟业务接口，不扩展 T06 任务、T08 审批或 T11 Agent。

初始工作区干净。本次仅使用模拟资金和模型替身，没有真实模型调用。实现未新增 Maven 或 npm 依赖。

## 已实现

- 独立订单、支付、回调数据与 HTTP 查询；金额整数分，支持 CNY，时间使用 Instant。
- 受控修复：重新核验订单状态/版本、支付成功事实、金额、币种及关联关系；订单变更和操作结果同一 PostgreSQL 事务提交。业务拒绝保存稳定原因，同 ID 同参数返回原结果，不同参数返回 409。
- 六个预置场景：回调失败、正常延迟、金额冲突、证据缺失、已修复、订单关闭；demo/test 首次初始化，重启不自动重置。
- 场景列表、单场景重置及两种故障。重置创建新订单 ID，保留历史证据和操作；旧订单新操作拒绝，旧操作幂等重放不影响新订单。
- 读、执行、管理三类 Bearer 凭证分离；缺少凭证拒绝业务访问；管理及故障仅在纯 demo/test profile 生效，非演示环境忽略历史故障。
- 参数校验、稳定错误码、中文说明、关联 ID；请求、HTTP 响应和持久化记录分离。

## 限制与后续依赖

- 正常延迟为近期支付与待送达回调的证据快照，不运行自动回调调度。等待决策属于诊断策略；符合业务条件的该场景可通过下游修复校验。
- 修复 API 是可信执行服务使用的下游契约，不验证上游审批；T08/T09 才建立审批与受控调用闭环。ADMIN 不能调用业务修复。
- 场景重置不撤销历史效果、不清理旧数据，长期反复重置会增长存储量。本次没有清空任何现有业务卷或数据库。
- T05 响应延迟是提交后的实际 HTTP 客户端超时测试；真实响应截断和独立进程 SIGKILL 恢复仍由 T04 测试负责。不能将 Spring 上下文重启测试称为 T05 的 SIGKILL 测试。
- 未执行真实支付、生产鉴权集成、真实模型评测或前端业务页面验收，这些不属于 T05。
