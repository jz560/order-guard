# T02：验证 Spring AI 接入

## 范围

依赖 T01。接入用户指定的 `deepseek-flash`，验证四个只读工具、应用控制的工具循环、结构化输出、记录、错误处理与预算。仅使用固定模拟证据，不实现完整业务工具、任务、审批、执行或恢复。

## 产物与契约

- `DeepSeekModelGateway`：Spring AI 2.0.0 官方兼容协议，固定 DeepSeek 地址与模型，非思考模式、无自动重试、30 秒请求超时、输出最多 1000 token。
- `ProbeTools`：`query_order/query_payment/query_callbacks/query_history`，仅接受 `{"orderId":"T02-ORDER-001"}`，严格字段和订单范围校验。所有结果带 `T02_FIXTURE` 来源和 evidenceId。
- `ProbeLoop`：调用前检查预算，记录模型意图/响应/用量/耗时，再验证并执行只读工具。默认 4 轮、12 个工具请求、同一固定查询最多 2 次、总时限 120 秒。停止后不继续请求。
- 最终输出：`recommendation` 为 `NO_ACTION/WAIT/MANUAL/RECOMMEND_RECHECK`，`reason` 为最多 1000 字符的简短结论，`evidenceIds` 只能引用实际查询证据且不得重复。建议重新核验必须引用四类证据，但不创建可执行方案。
- `ProbeTrace`：独立 runId、逐事件追加 JSONL 到 `.cache/t02-runs`。不保存认证信息或模型内部推理；供应商异常不直接进入记录。
- `T02Probe` 与 `scripts/t02-probe.ps1`：显式 CLI 入口，默认脚本替身；真实调用另需 `T02_ALLOW_LIVE=true`。常规 Maven 测试不触达外部模型。
- 无数据库迁移、无新 HTTP 业务接口、无前端变更。Compose 仅向 backend 传入可选 DeepSeek 密钥。

## 复现

```powershell
./mvnw.cmd -B -ntp '-Dmaven.repo.local=.cache/m2' spotless:apply verify
./scripts/t02-probe.ps1 -Mode stub
# 明确允许收费后，本机配置 DEEPSEEK_API_KEY
$env:T02_ALLOW_LIVE='true'
./scripts/t02-probe.ps1 -Mode deepseek
Remove-Item Env:T02_ALLOW_LIVE
```

本次实机 Java 21 路径通过进程级 JAVA_HOME 设置，未修改全局环境。模型别名可能更新，不能据此承诺供应商底层版本永久固定。

## 限制

- 本任务未重新构建或替换常驻 Compose 应用容器；交付验证使用 Maven 构建、Testcontainers 和命令行实验。前端无新增页面，因此未执行浏览器交互验收。
- 只验证接入与约束，不证明 Agent 的业务收益，T03 单独比较。
- JSON 和引用校验不能证明语义正确；不存在业务审批或执行入口。
- 超时取消本地等待不意味着远端未执行或未计费。
- JSONL 不代替 T11 的数据库持久化、权限上下文与恢复。
