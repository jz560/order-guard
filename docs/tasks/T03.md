# T03：验证 Agent 的初步价值

## 范围与交付

依赖 T02，使用用户已选的 deepseek-flash。比较完整信息规则、完整信息单次模型调用，以及从订单号开始的按需工具 Agent。没有新增业务写操作、数据库迁移、HTTP API 或前端页面。

- `backend/src/main/resources/evaluation/t03-cases.json`：12 个固定合成案例和评分预期，开发 8 个、预留 4 个。
- `PilotCases`：只向工具提供绑定订单及事实；标题和预期标签不进入模型上下文。
- `PilotRules`：与模型共享的明确政策，以及确定性完整信息对照。
- `PilotEvaluation`：三组实验、独立逐例日志、评分、分组汇总、案例/政策快照与哈希、整批 60 次请求限制。
- `ProbeEvidenceSource` 与 T02 `ProbeLoop` 的小范围扩展：复用已验证的预算、工具校验和记录流程，支持不同绑定订单、初始完整证据及禁用工具。
- `scripts/t03-evaluate.ps1`：默认 offline 只跑规则；deepseek 模式需显式授权开关，不复用 T02 的授权开关。

## 结论与限制

详细结果、失败案例和阶段决策见 [T03 对照报告](../evaluation/T03-report.md)，评分设计见 [决策 003](../decisions/003-t03-pilot-evaluation.md)。

规则与单次模型自动评分均 12/12，Agent 为 8/12，出现 1 次错误修复建议、1 次轮数耗尽和 2 次格式错误。Agent 证据读取量从 48 次降到 37 次，但模型用量和耗时更高；解释复核还发现 C09 的错误码指代偏差。整批保守估算费用 0.060199 元，不是实际账单。

**阶段决定：没有证明 Agent 相比规则的净收益，暂不扩大自主诊断范围。** 保留规则作为政策基线，将模型职责收窄为只读证据整理和解释；未来进入 T11 前另行验证语义校验、结构化输出与预算，不能凭本批结果接入审批/执行。没有推进其他开发任务。

此处政策边界明确，手工案例与规则同源，规则高分不等于已覆盖生产场景。预留组不用于根据模型反馈调参，也不能代替 T15 的独立评测。没有模拟真实业务网络时延；内存查询数量的减少只能证明选择性查询能力。
