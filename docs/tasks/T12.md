# T12 任务列表与诊断详情

## 范围与实现

依赖 T06、T11 已交付。本次实现 Vue 工作台：账号登录/退出、恢复会话、订单号/状态筛选与分页、新建诊断弹窗、重复任务跳转、任务详情、证据展开和引用定位。后端、数据库迁移和业务权限契约未修改；没有新增依赖。

- `frontend/src/api.ts`：同源会话请求、15 秒超时、一次 Basic 登录、CSRF 写请求、类型和显示文案。密码不存入浏览器存储；登录请求后清空输入。
- `frontend/src/App.vue`：哈希路由与详情恢复，按服务端 allowedActions 展示创建入口和读取能力，创建中禁用重复提交，失败重试沿用同订单幂等键。
- `frontend/src/EnvironmentStatus.vue`：保留原有服务健康检查，按用户展开并点击后查询。
- `frontend/vite.config.ts`：增加 `/api` 开发代理，共用 BACKEND_PROXY_URL，不把任何后端密钥注入前端。
- 详情仅展示服务端已校验结论；诊断事件按服务端发生顺序呈现公开元信息，不显示完整提示词、模型原始文本或内部推理。证据 UUID 关联到可展开快照，显示来源、查询时间、业务版本、完整业务 JSON；查询不可用与空记录明确区分。
- 未开始、加载、空列表、权限不足、会话失效、网络失败、停止原因和过期快照均有提示。切换路由后忽略迟到响应；重新打开页面读取当前服务端状态。
- 时间按 Asia/Hong_Kong 展示。证据金额以分表示。等待复查展示服务端 nextRunAt；不允许借重新诊断绕过任务限制。

## 启动与体验

1. 按 README 配置环境并 `docker compose up -d --build`。
2. frontend 目录 `npm ci`、`npm run dev`，使用终端显示的 URL（默认 5173）。
3. 使用 `.env` 配置的 operator / approver 密码。operator 可新建，approver 只读查看；订单号通过既有模拟场景 API 获取，见 docs/api/simulator.md。
4. 新建后进入详情，点击“刷新状态”读取后台结果；点击 E 编号展开证据。重复提交受限订单会打开原详情。

## 边界

- 本次是真实前后端与 PostgreSQL/模拟服务集成，但模型为工程替身；不证明真实模型效果。
- 当前手动刷新；SSE、审批/拒绝、取消、执行时间线及记录抽屉属 T13，尚未实现。T12 不提供这些写按钮。
- 详情/证据/诊断分别读取，后台可能在请求间推进；引用暂不可定位时明确提示刷新，不伪造证据。
- 请求幂等键只保存在当前页面内存中；关闭或重新加载后由后端活动任务约束继续防冲突，不宣称终态任务跨页面请求幂等。
- 无生产发布配置变化。静态 build/preview 不带 API 代理；正式托管仍需同源反向代理。
