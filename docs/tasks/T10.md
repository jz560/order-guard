# T10 取消与人工接管

依赖 T09。范围为后端取消、人工接管、核实结案、订单限制与处置审计；不推进 T11 诊断或 T13 页面。

## 实现

- 操作员可取消尚无执行意图的 QUEUED、DIAGNOSING、WAITING_APPROVAL、APPROVED 任务。取消与执行开始使用同一任务行锁、预期版本；只有一个转换能提交。取消后 FINISHED/CANCELLED，清除调度和租约并释放订单限制。
- 执行意图已提交时取消返回 409，自动确认继续，不能假装撤销业务效果。审批员可接管未结束任务，递增 epoch/version、停止自动调度并保留限制；旧 Worker 无法覆盖人工状态。
- 人工结案仅允许无执行意图的 NO_EXECUTION，或服务端查询原 operationId 并核实的 CONFIRM_OPERATION。成功必须同时验证当前订单和支付事实；明确拒绝保存原结果。未知、404、查询失败、参数不符或验证失败均保留限制。
- 新增 V6 task_handling 表，记录账号、原因、预期版本、结果、原操作和证据引用；数据库唯一约束支持跨重启重复提交，触发器禁止修改/删除历史。状态、证据、执行结果、记录、审计及限制释放在同一短事务中提交。HTTP 查询位于事务外，提交时重新校验。
- 新增 cancel、takeover、resolve、handling 四个接口，沿用会话、CSRF 和订单范围；身份只能来自认证上下文。allowedActions 按角色/状态返回取消、接管、结案和查看记录入口。

接口和示例见 [处置 API](../api/handling.md)，并发与保守处理决策见 [010](../decisions/010-t10-cancel-and-manual-resolution.md)。没有新增配置项。

## 验证

专项验证已通过：ExecutionIT 16 项、WorkerLeaseIT 10 项真实 PostgreSQL 测试，以及 T10HandlingIT 3 项独立 JVM/HTTP 测试，均无失败或跳过。

| 验收 | 实际证据 |
| --- | --- |
| 执行前可取消 | 两线程竞争取消与执行开始；排队/诊断中取消使旧 Worker 写回失败；审批重放不复活已取消任务 |
| 已开始不能假装撤销 | 已有意图取消 409，任务仍 EXECUTING，原执行结果继续进入 VERIFYING |
| 接管隔离旧 Worker | 接管后原租约写回失败，任务保持 MANUAL，无法再次自动认领 |
| 未知不能绕过限制 | UNKNOWN 接管后 NO_EXECUTION 和 404 核实均失败；新键创建同订单仍返回原任务，下游没有新增操作 |
| 明确结果才释放 | 原操作成功且事实核验通过、明确拒绝、确认无意图三条结案路径；成功证据和处置记录持久化；重复提交不重复落库 |
| 权限和原子性 | 角色/范围/CSRF/伪造身份/过时版本拒绝；审计失败回滚状态和 guard；记录禁止删除；取消跨 API 重启重放；人工核实在 API 重启后继续并支持成功后重复提交 |

## 边界与后续

使用真实 PostgreSQL、服务进程和 HTTP，但订单和资金均为模拟数据，没有真实模型调用。T10 未新增独立 kill 实验；完整回归沿用 T04/T09 的真实进程退出测试。T10 HTTP 未知场景由专用测试库构造恢复位置，再通过下游 HTTP 模拟迟到提交，不把这一构造称为真实进程退出。

接管不撤回已发出的请求。已有执行意图但下游始终 404 时仍保持限制，当前没有可靠的“未执行证明”协议或强制解锁入口。NO_EXECUTION 结案不表示修复成功。前端交互待 T13，本次没有部署或迁移既有演示数据库，也没有推送。
