# T06：完成任务创建与查询

## 范围与依赖

依赖 T01、T05；两项已有实际验收记录。开始时工作区干净，T05 提交为 `3f8b4b8`。本次只实现后端任务创建、列表、详情、订单限制、初始证据、基础审计与预置账号权限；没有新增前端页面、Worker、方案审批、取消、执行或模型调用。

## 已实现

- `POST /api/tasks`：验证操作员权限和订单范围，通过 HTTP 查询 T05 订单并校验返回字段，然后创建 `QUEUED` 任务。客户端不能指定身份、状态或诊断结论。
- 请求幂等键按认证账号绑定固定订单；同键同订单返回原任务，不同订单 409。不同键并发提交同一订单也只产生一个任务、一份初始证据。
- 任务、订单限制、初始订单快照、请求映射及审计在同一 PostgreSQL 事务提交；网络调用在事务外。数据库主键、部分唯一索引和延迟外键兜底。
- 查询列表（订单/状态筛选及分页）、详情、持久化证据和游标审计。刷新不执行诊断/修复；模拟服务离线时仍能查询和复用已有任务。
- 独立 `order_guard` 不因任务转人工自动释放；保留 UNKNOWN 限制的订单不能创建新任务绕过原任务。
- `operator` 与 `approver` 预置账号、服务端订单前缀范围、Basic 建立会话、CSRF 令牌、身份查询和受 CSRF 保护的退出。角色和 actor 来自认证上下文。demo/test 之外禁用预置账号；密码为空也禁用账号。
- 稳定错误码、中文错误说明、关联 ID 与包含 taskId 的创建日志；不输出凭证、堆栈或 SQL 参数。

## 限制与后续任务

- T06 任务停留在 QUEUED；T07 才实现后台推进。详情的 allowedActions 只列出已实现的只读操作，没有虚假的取消、审批或执行入口。
- 初始证据仅为创建时订单快照，不能当作执行时最新事实。支付、回调和 Agent 循环证据属于 T11；业务状态变化时应由后续执行前复核处理。
- 订单前缀是演示级权限范围，并非生产多租户授权系统。预置密码来自环境，运行时 BCrypt 编码；没有账号管理后台或生产身份提供商。
- 会话不持久化到数据库，后端重启后需要重新认证并获取 CSRF 令牌；任务、证据、订单限制和审计持久化保留。独立进程重建验证不等同于 T04 的 SIGKILL 崩溃窗口实验。
- T06 不释放订单限制；转人工/结果未知时限制保留。未来 T09/T10 负责确认业务结果及安全释放，不能直接按任务终态删除限制。
- 列表 items 与 total 为两次查询，并发新增时可能暂时不一致；不提供历史一致性快照。
- 未重建或部署常驻 Compose 服务；未运行真实模型或真实支付，也未开发/验收前端任务页面。
